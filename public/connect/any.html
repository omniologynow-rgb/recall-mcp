Any MCP client

Recall is a standard MCP server. If your client speaks MCP — today's, tomorrow's, one that doesn't exist yet — it speaks Recall. That's the whole point: your memory should never depend on a client list.

The three facts you need

Endpointhttps://recall-mcp.fly.dev/mcp
TransportMCP Streamable HTTP, stateless (plain JSON responses; no session or SSE required, initialize optional)
AuthAuthorization: Bearer recall_live_… — or ?key=recall_live_… in the URL for clients with no header field

Generic config

Most clients accept some variant of this JSON (field names vary — url / serverUrl / httpUrl):

{
  "mcpServers": {
    "recall": {
      "type": "http",
      "url": "https://recall-mcp.fly.dev/mcp",
      "headers": { "Authorization": "Bearer recall_live_YOUR_KEY_HERE" }
    }
  }
}

Client only takes a URL?

https://recall-mcp.fly.dev/mcp?key=recall_live_YOUR_KEY_HERE

Issue a dedicated key for URL-based clients (label it) so you can revoke it independently — managing keys.

Client only speaks stdio?

Bridge it with mcp-remote:

{
  "mcpServers": {
    "recall": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://recall-mcp.fly.dev/mcp",
               "--header", "Authorization: Bearer recall_live_YOUR_KEY_HERE"]
    }
  }
}

Prove it with curl

It's just HTTP — no SDK required. List the tools:

curl -X POST https://recall-mcp.fly.dev/mcp \
  -H "Authorization: Bearer recall_live_YOUR_KEY_HERE" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Store a memory:

curl -X POST https://recall-mcp.fly.dev/mcp \
  -H "Authorization: Bearer recall_live_YOUR_KEY_HERE" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"remember","arguments":{"content":"My dog is named Biscuit."}}}'

The five tools

rememberStore a memory (content, optional namespace + metadata). Deduplicates identical content.
recallSemantic search over your memories, ranked by similarity.
list_memoriesPage through memories, optionally by namespace.
update_memoryEdit a memory's content or metadata (re-embeds).
forgetDelete by ID, or by query with a two-step preview → confirm.

The 30-second test

Tell your AI: Remember that my dog is named Biscuit.
Start a new session — or a different client entirely. Ask: What's my dog's name?
If it says Biscuit — your memory is live everywhere.
